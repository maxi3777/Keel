# Keel — Authoritative Notebook

Keel is your notebook ("The palest ink is better than the best memory"). It records what must not be forgotten or silently changed — the root page (requirements, weighted principles, global decisions, cross-module invariants), module pages (module-scoped requirements and concept models), the global glossary, protected documents — and keeps it authoritative. Beyond the guarded record and the glance habit, Keel does not direct how you think or work.

## Iron rules

1. **Semantics are yours; determinism belongs to the server** (the process behind the `keel_*` tools). Every write under `.keel/` goes through `keel_*` tools — never edit the files by hand. Reads are free: every notebook file (DATUM.md, INDEX.md, pages/\*, AMENDMENTS.md) is plain markdown — open what you need directly; `keel_digest` is the map (injected at session start and refreshed after every confirm), not the gate.
2. **Write for the whole lifecycle.** Every line that enters a page or the amendment log must be intelligible in any later session, to a reader who does not have this conversation's context: no private abbreviations, no shorthand only the current dialogue makes readable, no coined term left unregistered (rule 5). A line that needs "you had to be there" is not finished. Clarity is the bar — the server enforces no quantity checks.
3. **The glance habit.** After you finish a plan and before implementing, check the plan against the digest: the **root pins** (goal, scope, requirements, P\*, invariants, decisions) apply to every plan; the **INDEX covers** route you to module pages. Match, do not bulk-read: name what the plan touches, read only the matched pages. A provably unrelated plan reads nothing — say "zero matches" in one line and proceed. Memory of a page is evidence, not the source: if a page's `lastAmend` moved after you last read it, re-read it. On conflict: propose an amendment, drop the change, or — with the user — record an explicit exemption (`keel_exempt`, reason required). Silent divergence is forbidden. Disagreeing with the notebook is legitimate: propose the change with rationale; the notebook is authoritative, not sacred.
4. **Phases are per-page.** A page starts draft: its writes apply immediately, logged `ai-managed`. When you judge a page's essentials recorded in language that survives the session (rule 2), declare that page authoritative yourself — `keel_config {authoritative:true, page}` (page defaults to root) — one-way per epoch (an epoch = a page's generation, +1 per reopen), and **announce it to the user at that moment**: consent and steward now apply to that page (the switches are project-level, default ON; a `notebook:true` project starts with both OFF — the user can flip either on anytime). Reopening an authoritative page (`keel_config {phase:'draft', page}`) is user-directed: the server snapshots the page, drops its pending proposals, and reports what needs re-affirming. `keel_config {consent, steward}` flips the project switches anytime, either way — the user decides.
5. **Terms**: name a load-bearing concept from its purpose, in the user's vocabulary where possible, and register it on the terms page via `keel_glossary_register` in the same turn it first appears. The glossary is global — one vocabulary across all pages. When one word carries two meanings, the glossary row is the arbiter: cite it and resolve the conflict on the spot.
6. **Oscillation is a reference metric only** — how often one position is amended by overturning earlier amendments (≥2 reversals at the same position since the last compaction); never a threshold, never a gate; always label it as such when presenting.
7. **Two protection mechanisms, matched to the object**: writes to authoritative surfaces = consent-gated while consent is on; protected references (listed in INDEX) = tamper-evidenced (SHA-256 verify — report, never block); everything else = unprotected. Respond at the matching strength: stage and ask for the first, report mismatches for refs, write freely elsewhere.

## Operating notes

- One skill, natural language: the user describes what they want and you map it to tools. No slash subcommands.
- Starting: `keel_init {project}` creates the routed notebook (root page + INDEX + terms page + log). `notebook:true` for a pure-notebook project (both switches stay off).
- Module pages: `keel_page_add {name, covers}` when a module needs its own addressable home — a single-module project simply never adds one. `covers` = stable anchors (repo paths/globs, glossary terms, claim ids); routing quality depends on them. Update with `keel_page_covers`; retire with `keel_page_remove` (snapshots to archive).
- Claim ids (`Requirement R-n`, `P-n`, `Decision D-n`) are globally unique across all pages — pick numbers no other page uses; the server rejects collisions.
- Read `references/notebook.md` when authoring or amending pages (layout, drafting, per-page activation, consent flow, module pages, reopen, protected references).
- Read `references/steward.md` for the glance / post-plan check protocol, session bootstrap, and maintenance.
- Iteration tools are separate skills (`keel-stress-test`, `keel-alternatives`, `keel-relax-probe`, `keel-skeleton`); adopted findings come back through this module's write path.
