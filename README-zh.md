# Keel（龙骨）

**Keel 把"设计"从聊天记录里抽出来，变成一份权威文档——概念层与你共同推导、逐步讲解；此后在每一个会话中被持续守护，防止需求漂移与设计退化。**

> 造船先铺龙骨，船体后续所有测量都以龙骨为基准。Keel 对软件设计做同样的事：概念设计先行铺下，之后所有会话的改动都对照它来度量。

Keel 是一个面向 AI 编码宿主（Claude Code、ZCode 及其他 MCP 兼容 agent）的插件，由零依赖的 Node.js MCP server、一个 skill 和一个会话钩子组成。

**English documentation: [README.md](README.md)。**

---

## 为什么需要 Keel

如果你和 AI agent 一起设计过软件，大概率遇到过这四件事：

1. **报告读不懂。** agent 交给你一个成品结构——模块、调用、目录——附带一点注释，但从不解释"它为什么长成这样"。读起来像带注释的代码，因为设计的**推导过程**从来不是一等产物。
2. **需求遗忘。** 需求只活在对话里。十个会话之后悄悄走样，没有任何东西发现。
3. **迭代退化。** 让 agent 改进自己的设计，它就在成品上打补丁：v6 是历史沉积物，看不出最初的意图。
4. **参与度错配。** 要么你全程盖章，要么你被拖进本不想裁决的实现细节。

Keel 的解法是一个同时命中四点的机制：一份**刻意限定层级**的权威设计文档（DATUM），外加一套修订协议。需求在你说出的那一刻就被编号固化；概念设计必须以可攻击的分步推导链呈现；你的参与度随设计下沉而**按阶段递减**；DATUM 一旦存在，之后所有会话都有常驻守护，拒绝静默分叉。

## 核心概念

### 按保护级别组织的文档集

Keel 不维护一份大而全的设计文件，文件沿**保护级别**切分，而不是按大小：

```
L1  事前强制（write-gating）   DATUM.md —— 受保护核心
L2  事后检测（tamper-evidence） protected references（你的其它文档，hash 核对）
L3  事后审计（reconcile）      代码 vs 契约索引
L0  无保护                     TECHNICAL.md —— 派生、可重生成、不设防
```

```
.keel/
├─ DATUM.md       受保护核心：00 意图（目标/边界/编号需求）· G 术语表
│                 · 01 概念（原则 P* + 概念模型 + 停车场）· 02 取舍台账
│                 · 03 契约索引（每个契约一行，带 implements: P* 与 detail 链接）
│                 · R 受保护引用
├─ TECHNICAL.md   派生展开：T1–T9（模块边界、接口契约、数据模型、状态机、错误策略、
│                 选型+版本、验收标准、非功能约束、风险），每项经 contracts: Cn
│                 回链索引——plan/build 的直接消费对象
├─ AMENDMENTS.md  append-only 历史：谁在何时改了什么、经谁同意；
│                 压缩归档（archive/，永不删除）
├─ handoff.md     G2 后的机械打包（DATUM + TECHNICAL）
├─ probes/ · archive/
```

两条规则保证它可信：

- **层级契约。** DATUM 的成员资格判据是*不可退化性*：它以薄薄的契约索引跟踪设计级事实（原则、概念模型、契约、归属、选型）；完整的技术展开是派生文档，原则上可从核心重新生成。什么都想守护的文档必然腐化、失去权威。
- **同意分级。** 核心修改（需求、原则、概念模型、契约索引、受保护引用、承重术语）阻塞到你明确同意为止，你的同意原话作为审计凭证存档；外围修改立即生效、批量告知。哪种算哪种由 server 计算，不靠 AI 自觉。
- **受保护引用。** 你的其它文档（别的工作流生成的 API 规范、架构笔记等）可以被*准入*防退化范围：Keel 记录其整文件 hash 并按需核验。这里的保护是事后检测而非写入管制——文档所有者自由编辑，分叉被检测和报告，但从不拦截。

### 推导链

概念期里，agent 不许直接交结构图，必须展示：

```
D1 需求事实    只引用编号需求，不凭记忆
D2 张力        哪些需求互相冲突、卡在什么约束上
D3 关键认识    每条标注 [事实] / [假设] / [推断]
D4 原则候选    3~5 条编号原则，每条注明化解了哪个张力
D5 概念模型    实体/流/不变量，日常词汇，禁止类名
D6 被弃路线    至少一条完整备选 + 弃因
```

你可以攻击任何一步；agent 展示波及（后面哪些步随之变），给出修订链并记账。原则签收时跑**骨架测试**：一个无上下文的子代理只拿需求和原则去重建概念模型——重建不出来，说明原则只是装饰，不是骨架。

### 阶段与参与度递减

```
你的参与度
高 │  共创：挑战推导步、裁决分叉、签收原则                    ← 概念期
中 │        只做决策：选择题菜单                              ← 技术期
低 │              被告知；仅冲突时裁决                        ← 交付 / 常驻守护
   └──────────────────────────────────────────────────▶ 时间
        推导、执行、记忆、纪律全程由 agent 承担
```

- **概念期**——共同推导。默认单候选；只在真实分叉处给 2~3 条完整推导链。
- **技术期**——agent 细化九个技术项，你只回答决策菜单（选项 + 推荐 + 理由 + 选错代价）。交付物的具体度基准：*plan/build 阶段拿到后不需要再做任何设计决策*。
- **交付**——server 机械快照 `handoff.md`，直接喂给你惯常的 plan/build 流程。
- **常驻守护（STEWARD）**——从此以后，每个会话（见下文）。

### STEWARD 常驻的具体形式

"常驻"由三件具体的东西构成，而不是一句口号：

1. **SessionStart 钩子（机械）**：`hooks/hooks.json` 注册了会话启动命令。若工作目录存在 `.keel/DATUM.md`，钩子打印核心的**原文摘录**——首行是**文档指针**（路径 + 访问方式），让同会话的任何其它工作流都能找到并基于核心派生——随后是目标、边界、需求、原则、头部契约、头部术语、受保护引用、最近修订。它不是 AI 摘要，不可能幻觉——由代码从文档本身切片。**PostToolUse 钩子**还会在每次核心修订落盘后刷新摘录，长会话无需重启即可跟踪设计变化。
2. **skill 触发（行为层）**：skill 描述告诉宿主"只要存在 `.keel/DATUM.md` 就加载 Keel 协议"，从而激活行为规则：动手前判问、冲突即停、修订/放弃/豁免三选一。
3. **MCP server（机械兜底）**：即使以上两层都失效，DATUM 的写入也只能走 server——核心修改必须暂存到同意为止。通过受支持的路径，无账分歧在机制上不可能发生。

## 一个完整例子

你：`/keel 我要把选中文字发给 AI 提问，追问要能引用之前选过的内容`

agent 抽取编号需求（R1 选中即问；R2 追问可回指早前选择），向你确认后推导：

```
D2  张力："当前选择"是瞬时的，"会话上下文"是持久的——生命周期不同。
D3  认识 [假设]：选择内容属于会话上下文，不属于单次请求。
D4  P1：用户操作改变上下文，不直接发起请求。
    P2：会话是上下文的唯一权威源。
D5  用户动作 → 上下文事件 → 会话状态 → 请求
D6  被弃：直接拼 prompt 发请求——追问时"刚才选的内容"已无处可寻。
```

你："D3 不对——选择内容有时效，过期就不该再被引用。"

agent 展示波及（D3 变为带生命周期的上下文事件 → P2 增加过期规则 → 模型增加过期流），征得你同意后在台账记账。注意全程**没有出现一个类名或技术选型**，但设计的实质变了，且变动有账可查。

之后某个不相干的会话里你说："加一个多选文本合并提问"。摘录早已在上下文里；动手前判问发现触碰 P2 和契约 C3；agent 停下来给你三个选项：修订 DATUM（带波及）/ 放弃 / 显式豁免。需求不会悄悄走样——这就是全部的意义。

## 安装

**前置**：Node.js ≥ 18（MCP server 零 npm 依赖）。

### 从插件市场安装（推荐——Claude Code、ZCode 及兼容宿主）

本仓库同时就是自己的插件市场，安装方式与 Superpowers 这类市场插件完全一致：

```bash
claude plugin marketplace add maxi3777/Keel
claude plugin install keel@keel-marketplace
```

交互会话里同样的两步是斜杠命令：`/plugin marketplace add maxi3777/Keel`，然后 `/plugin install keel@keel-marketplace`。（命令语法不同的宿主，如 `$plugin`，执行的是同样两个操作；插件名都是 `keel`。）

安装一次注册全部三个组件：

- **MCP server**（`.mcp.json` → `node mcp/server.js`，相对插件根解析）；
- **skill**（斜杠命令宿主上是 `/keel`；skill 描述还会在 `.keel/DATUM.md` 存在时自动触发常驻 STEWARD 模式）；
- **SessionStart 钩子**（`hooks/hooks.json`，`$CLAUDE_PLUGIN_ROOT` 由宿主展开为插件路径）。

日后更新：`claude plugin marketplace update keel-marketplace` 后重装，或在添加市场时钉住版本（`maxi3777/Keel@v1.0.0`）。

可选：克隆仓库做机械层端到端验证：

```bash
git clone https://github.com/maxi3777/Keel.git
node Keel/tests/smoke.js     # 预期输出：SMOKE PASS
```

### Codex CLI

Codex 没有一步到位的"MCP + skill"市场通道，使用内置适配器：

```bash
node adapters/codex/install.js     # --uninstall 卸载
```

它把 skill 复制到 `~/.codex/skills/keel/`（同样的 SKILL.md + references/ 结构），并向 `~/.codex/config.toml` 追加 `[mcp_servers.keel]`。Codex 没有会话钩子，走文档化的降级路径：agent 在会话开始和确认后主动调用 `keel_digest`——强制力不受影响（写入仍被 server 把门）。详见 [`adapters/codex/README.md`](adapters/codex/README.md)。该路径已在 codex-cli 0.153.4 上用三个多轮设计主题（概念→交割→守护，含受保护引用与压缩）端到端验证。

### 其他 MCP 兼容宿主（手工接线）

1. **MCP server**——加入项目的 `.mcp.json`：

   ```json
   {
     "mcpServers": {
       "keel": { "command": "node", "args": ["/绝对路径/Keel/mcp/server.js"] }
     }
   }
   ```

2. **skill**——把 `skills/keel/` 复制或链接到宿主的 skills 目录。

3. **会话钩子（STEWARD 自举）**——在宿主设置里注册会话启动时执行 `node /绝对路径/Keel/hooks/session-start.js`。宿主不支持钩子时，skill 降级为会话开始主动调用 `keel_digest`——失去的是自动注入，不是强制力（写入仍被 server 把门）。

**验证**：在临时目录里对 agent 说 `/keel 测试项目`——应看到 `.keel/DATUM.md` 被创建、抽取的需求请你确认；`/keel status` 应显示 `phase=concept`。

## 按阶段与场景使用

### 开始一个新设计

输入 `/keel <你想要什么>`，确认抽取的需求，然后通过攻击推导链的步骤（D1–D6）完成全部工作：不认同问题框架就攻击早期步骤；怀疑事实就攻击 D3 的 `[假设]` 项。

### 概念期迭代

`/keel iterate <技术>`，可选：`assumption stress-test`（假设压力测试）、`alternative insight generation`（备选认识生成）、`constraint-relaxation probe`（约束松弛探测）、`skeleton test`（骨架测试）。每次调用先声明预测、事后记录偏差——迭代可审计且层级封顶（技术层产出进停车场，概念文档保持简单）。

### 签收：G1

概念收敛后，你**按优先级顺序**签收原则，机械门检查，骨架测试尝试只凭原则重建概念模型。全部通过才解锁技术期——server 拒绝越阶段前进。

### 技术期：做决策，不读全文

你只会看到决策菜单。选择自动进台账。九项填齐（每项带溯源）、你过目摘要后 G2 通过，`handoff.md` 快照产出——喂给你惯常的 plan/build 流程。

### 之后的任何会话（STEWARD）

正常干活即可。摘录自动在上下文里；任务触碰设计层时，agent 停在冲突处给出修订/放弃/豁免。常用命令：

- `/keel status`——阶段、门、未决提案、外围变更批量告知、健康摘要。
- `/keel check <改动>`——"这个改动碰不碰设计层？"（溯源闭包，T→C→P 联结；同时列出疑似过期的受保护引用）。
- `/keel amend`——主动提出设计级修改。
- `/keel protect <path>` / `/keel unprotect <ref>`——把派生文档准入/移出防退化范围（准入时记录 hash；核验只报告分叉、从不拦截）。核心修订落盘时，Keel 会报告哪些受保护文档从此过期——由负责的工作流重生成。
- `/keel reconcile`——对照契约索引审计代码并重核受保护引用的 hash；漂移标注为"文档过时"或"代码越轨"。
- `/keel digest`——随时重看摘录。

### 维护

修订日志增长后 `keel_status` 会建议压缩：agent 把被覆盖条目合并为摘要，server 把原文逐字归档到 `.keel/archive/`（永不删除）。健康摘要用两种口径报告核心修改频率——自上次压缩（黄旗依据，始终显式标注）与终身计数（永不重置）——外加**振荡**计数（同一位置来回修订 ≥2 次）——全部是*参考指标*：Keel 刻意不设阈值。另有两个机械便利保证账目诚实：跨区段的修订以**一次批量提案**发出（一次同意、一行日志）；项目处于 handoff 阶段时，每次设计修订都会**自动滚动刷新 `handoff.md`**，被替换的版本冻结到 `archive/handoff-<n>.md`，头部标注 `Snapshot @ amendment #N`。

## 强制力到底从哪来

| 层 | 机制 | 保证 |
|---|---|---|
| skill | 行为协议 | 引导 agent（尽力而为；提示词会衰减） |
| 钩子 | 会话启动注入 | 每个会话以设计原文摘录开局 |
| MCP server | 唯一合法写入口 | 核心写入暂存至同意；外围写入溯源闭包触核心时自动升级；门未过不得推进阶段；append-only 日志带同意凭证 |

分工是本项目的一条公理：**AI 产出语义（写什么），代码执行一切确定性动作（落在哪、什么格式、过哪些检查）。**

## 研究背景与参考文献

Keel 浓缩了两轮"调研 + 实验"研究（智能体问题求解策略 / 自驱动设计改进；合计调研 94 项工作、384 轮对照迭代实验）。下表列出采用的论文及刻意偏离之处（完整对照见英文版 [README.md](README.md) 的 References 表，含 arXiv 链接）：

| 论文 | 出处 | Keel 采用点 | 刻意偏离 |
|---|---|---|---|
| Huang et al., *When Can LLMs Actually Correct Their Own Mistakes?* | TACL 2024, arXiv:2406.01297 | 自我纠错仅在外部信号下成立 | 把"信号"操作化为骨架测试的子代理重建与代码对账，而非对答案的工具反馈 |
| Shinn et al., *Reflexion* | NeurIPS 2023, arXiv:2303.11366 | 语言化反思跨轮持久 | 反思被记账为带同意与波及的修订条目，而非自由文本记忆 |
| Madaan et al., *Self-Refine* | NeurIPS 2023, arXiv:2303.17651 | 自迭代反馈结构 | 仅在有外部记录（预测 vs 偏差）时使用；无信号的纯自评不被信任 |
| Agrawal et al., *GEPA* | ICLR 2026, arXiv:2507.19457 | 反思式候选进化、Pareto 保留 | 只取"反思后修订"；增加预测声明；纯手动调用，无自主外环 |
| Zhang et al., *ACE* | ICLR 2026, arXiv:2510.04618 | 上下文增量演化与压缩 | 压缩不删历史（archive/）、加人工告知、按复用晋升 |
| Nguyen et al., *RSEA* | 2026, arXiv:2606.28374 | held-out keep-better 单调选择 | 数值目标换成"优先级冲突升级给用户"（原则是可权衡的优先级） |
| Ye et al., *ReEvo* | NeurIPS 2024, arXiv:2402.01130 | 失败中提炼"语言梯度" | supersedes 链记录同类知识；其上的振荡统计是新的 |
| Liu et al., *EoH* | ICML 2024, arXiv:2401.12137 | 思想/产物共进化种群 | 种群退化为被弃路线档案（D6），假设变化时人工重开 |
| Romera-Paredes et al., *FunSearch* | Nature 625 (2024) | 保留最优候选的程序库 | 同样的 keep-best 档案语义，对象换成设计推导 |
| DeepMind, *AlphaEvolve* | 2025, arXiv:2506.13131 | 进化数据库与谱系 | 谱系 → 修订日志；进化循环本身不在范围内 |
| Hu et al., *Darwin Gödel Machine* | ICLR 2026, arXiv:2505.22954 | 基于档案的开放式自我改进 | 只取档案概念；无自指式自我修改 |
| Zhao et al., *ExpeL* | AAAI 2024, arXiv:2308.10144 | 经验蒸馏 | 已考虑，v1 暂缓（修订日志即最小经验层） |
| Wang et al., *AWM* | 2024, arXiv:2409.07429 | 工作流记忆 | 已考虑，v1 暂缓 |
| *Magentic-One* | 2024, arXiv:2411.04468 | 任务/进度双台账 | 弃用：DATUM 刻意只做单一账本 |

## 局限与刻意不做

- Keel 服务**深度参与者**。只盖章不挑战，概念期就是表演。
- 低于复杂度门槛的任务，仪式成本大于价值；agent 应当劝你换轻量流程。
- 单一设计权威：v1 不处理多 agent 并发写同一份 DATUM。
- 不做自主设计进化：Keel 刻意不跑无人值守的外环。
- 完整规范（含失效模式与研究出处表）见 [`docs/PROTOCOL.md`](docs/PROTOCOL.md)。

## 开发

```bash
node tests/smoke.js   # 端到端：真实拉起 server，走完 init → 同意 → 门 → 交付 → 压缩
```

仓库结构：`.claude-plugin/`（插件清单 + 市场清单）· `mcp/server.js`（server）· `skills/keel/SKILL.md` + `skills/keel/references/`（agent 协议：分发器 + 分阶段细则）· `templates/`（DATUM / TECHNICAL / AMENDMENTS）· `hooks/`（会话自举 + 确认后刷新）· `docs/PROTOCOL.md`（规范）· `tests/smoke.js`。
